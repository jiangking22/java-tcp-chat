# Java TCP 聊天室开发规约

面向本机及受信局域网的课程演示。以固定版本的 MIT 上游工程为基线，保留 Java Socket 客户端、线程式服务端、聊天指令和指标采集。使用 JDK 21 标准库。原始来源和改动范围记在项目根目录的 ATTRIBUTION.md。

## 功能与可验收规格

| 编号 | 规约 | 验收方式 |
| --- | --- | --- |
| F1 | 多客户端可注册、登录、加入或退出房间。普通消息只发给同房在线用户，私聊仅发给指定在线用户并向发送方确认。 | 执行上游集成测试。用三个 TCP 客户端验证中文广播、跨房隔离和切房后的送达。 |
| F2 | 网络文本使用 UTF-8。客户端发来的每条消息以 LF 或 CRLF 结束，正文最多 4096 字节。服务器拒绝超长帧、非法 UTF-8 或未跟随 LF 的 CR，关闭该连接，其他会话可继续收发。 | 验证 4096 字节加 CRLF 可以转发。仅发送 4097 个正文字节也应收到拒绝响应。补测非法 UTF-8、正文 CR、断线清理与后续通信。 |
| F3 | 昵称为单个词，占用应原子判定，正常退出或 EOF 后释放。账号在同一次服务端运行中保留，密码最多试三次。账号大小写采用与在线昵称相同的比较规则。 | 执行无效昵称、重复昵称、错误密码、关闭连接后重新使用同一账号的用例，检查连接计数。 |
| S1 | 聊天和诊断端口默认监听本机回环地址。仅显式设置 CHAT_HOST 才向指定局域网地址开放聊天端口。注册密码在内存中以随机盐和派生摘要保存。 | 检查绑定和密码处理代码，运行登录、重连和本地指标测试。实验使用临时密码，TCP 链路明文。 |
| P1 | 在本机以 20 客户端、2 房间、10 条每秒、10 秒运行压测，所有客户端建立连接，发送错误为 0，收集实际送达数和端到端延迟。 | 通过 chat.ps1 load 或等效 Java 命令运行压测，保留参数和控制台原始输出。延时与吞吐按实测记录。 |

## 实施与回归

1. 固定并核对上游版本，构建上游测试基线。
2. Codex 根据 F1–F3 生成真实 TCP 验收用例，先确认用例能捕获旧实现的协议限制缺口，再实现最小改动。
3. 完整执行上游测试、课程验收和压力测试。记录 JDK、命令、实际结果及任何偏差。解释 S1 的信任边界。
4. 测试失败时先核对规约与观察结果，再修订实现或明确修订验收边界。使用专用目录和回环地址复现。涉及公网发布、真实凭据或不可逆操作，交由人工审批。

## 入口与目录

- src/ 是服务端、客户端和指标端点。
- test/ 是可独立运行的集成测试和课程验收用例。
- tools/ 是负载生成器。
- 在项目目录执行 .\chat.ps1 build 和 .\chat.ps1 test。
- 用 .\chat.ps1 server 和 .\chat.ps1 client 启动程序。README.md 提供完整操作命令。
